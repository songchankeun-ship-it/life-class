# Aide 아이폰 앱 전환 · 2026-10-22

목표는 기존 Aide의 데이터와 PC 연동을 공유하면서 단축어 설정 없이 실제 iPhone AlarmKit 알람을 관리하는 것이다. 기존 Safari PWA·Cloudflare D1 데이터·아이폰 Web Push·매일 브리핑·Claude 월 30,000원 상한을 대체하거나 초기화하지 않는다.

## 구현

1. 기존 모바일 UI를 WKWebView로 제공. 네이티브 bridge는 운영 HTTPS 최상위 프레임에만 허용하며, 알람 전용 기기 연결/동기화 명령만 받는다. 서버 owner key를 bridge로 전달하지 않는다.
2. 반복 월~금 08:30과 날짜 지정 알람, 5/10분 다시 알림. 반복 요일·24시간제·한국 시간은 공통 모듈에서 정규화한다. 서로 다른 요일/날짜를 혼합하거나 불가능한 날짜·모호한 오전/오후는 거부한다.
3. PC와 앱의 ‘아이폰 앱 알람’에서 설정 검토 후 별도 승인. 생성 요청 ID로 중복 재시도 방지. 일정 레코드와 알람 요청을 원자적으로 저장. 일반 알림과 이중 발송하지 않는다.
4. 기기가 AlarmKit에서 실제 ID/날짜/시각/반복 요일/다시 알림 간격을 읽어 회신한다. 서버는 현재 버전·기기 전용 키·서명 challenge·요청 설정을 비교한다. 오래된 확인·APNs HTTP 200·서버 저장만으로 ‘예약 확인’ 표시하지 않는다.
5. PC에서 알람 취소 요청 가능. 일정은 남기고, 실제 아이폰 취소를 읽어 회신할 때까지 ‘취소 대기’. 종료/완료/알림 해제도 기기에 전달해야 실제 알람에 적용된다.
6. 잠금 화면 Live Activity Widget 동봉. 앱/위젯을 함께 빌드하고 각각 서명한다.

## 사용 경계

첫 실행은 ‘연결·알람’ 탭에서 미완료 단계 하나만 보여준다. ‘일정 연결 → 아이폰 연결 → 알람 허용’ 순서이며, 화면마다 짧은 안내와 주 동작 버튼 하나를 둔다. 일정 연결 버튼은 웹의 코드 입력 부분으로, 아이폰 연결 버튼은 앱 안 알람 연결 화면으로 이동한다. 이 안내에서 연결을 시작한 경우 연결 정보가 감지되면 안내 탭의 다음 단계로 돌아온다. 기존 연결은 다시 시작하지 않으며 완료 상태는 저장된 연결과 현재 권한에서 판단한다. 수동 코드·문제 해결·예약 상세는 접어 둔다.

웹 화면의 준비 신호를 받은 뒤 이동하므로 초기 로딩 중 요청도 사라지지 않는다. 웹 연결 키의 유무만 Boolean으로 네이티브에 전달하며 키 자체는 전달하지 않는다. 연결 정보가 있다는 표시를 서버 동기화 성공으로 간주하지 않는다. 마지막 안내의 ‘연결과 권한 설정 완료’와 실제 알람 예약 확인을 구분한다.

네이티브 화면은 기기에서 읽은 예약 결과와 PC의 결과 접수를 별도로 보여준다. PC 전송이 실패했거나 이전 확인 시각이 오래됐으면 현재 PC 확인 성공으로 표시하지 않는다. 직접 숫자 코드를 입력하는 방법은 보조 메뉴에 접어 두며, 웹 연결 코드와 혼동하지 않도록 구분한다. 새 앱 내부에서는 Safari 홈 화면 추가·웹 푸시 권한 안내를 숨긴다. Safari 앱의 실제 푸시 등록에는 영향을 주지 않는다.

- 새 요청·변경·취소는 아이폰이 받아야 한다. APNs 백그라운드 실행은 iOS가 제어하므로 PC에서 입력하는 순간 항상 즉시 예약된다고 보장하지 않는다. 앱 열기와 기기 확인 상태를 제공한다.
- 이미 아이폰에 예약된 AlarmKit 알람은 PC를 꺼도 기기에서 실행된다. 기본 시계 앱의 목록과는 별도다.
- 월~금 반복은 단일 예약 규칙이다. 날짜가 지나도 만료시키지 않는다. 반복 요일 변경은 현재 알람 취소 후 새 규칙 승인으로 진행한다. 날짜 지정 알람은 연결된 일정의 날짜/시간 수정 뒤 새 기기 응답이 필요하다.
- 현재 반복은 한국 시간대인 기기에서만 예약한다. 해외 시간대에서는 실패 이유를 보고한다.
- 네이티브 타이머 실행부와 Siri App Intent 호출은 이번 범위에 미포함. 기존 PWA 기능은 유지한다.

## 아직 완료되지 않은 것

운영 알람 기능 스위치는 꺼져 있다. 새 평일 08:30 알람과 날짜 지정 알람을 실제 사용자 아이폰에 생성하지 않았다. 기존 사용자가 직접 수정한 10월 23일 10:00 시계 알람은 그대로 둔다. TestFlight 배포 서명, 설치, 잠금 상태 울림, 다시 알림과 중지, PC의 실제 기기 확인은 설치 후 검증해야 한다.

## 설치 순서 / 비용 경계

1. 무료 코드·서명 없는 iOS SDK 빌드·서버/화면 검증 완료.
2. 사용자에게 Apple Developer Program 연회비 US$99/지역 현지 가격 안내. 결제 승인 전 가입·결제·서명 자산 생성·업로드 중단.
3. 소유자가 가입/계약을 확인하면 App ID/Widget ID 및 배포 프로파일 2개 구성, TestFlight 수동 배포. 현재 Mac 구매가 필요한 경로로 잡지 않고 기존 공개 저장소의 표준 macOS CI 활용.
4. 아이폰 앱 설치 → 앱 안에서 기존 Aide 일정 연결 → 네이티브 알람 기기 연결/권한. 전용 키는 Keychain에 보관한다.
5. 운영 스위치 활성화. 평일 08:30 설정 내용 승인. 날짜 지정은 기존 재입고 알람과 중복되지 않는 별도 시험 1건으로 기기 예약/울림/중지/다시 알림 검증.
6. PC에 실제 읽기 응답이 보이고 아이폰 울림을 사용자가 확인한 뒤 사용 가능으로 안내.

사용자는 2026-10-22 결제를 다음 날로 미뤘다. 결제 또는 가입 완료로 간주하지 않으며 오늘은 앱 연결 화면·무료 unsigned 빌드·설치 안내 준비만 진행한다. 기존 Apple 결제 화면에서 129,000원(VAT 포함)을 확인했지만 최종 주문과 멤버십 활성화는 확인하지 않았다.
